1. 项目概述

1.1 背景

个人交易者在实际交易中存在四个断裂：

  1. 选股与决策断裂：看盘软件能给出信号，但给不出"在什么区间买、什么区间卖、买多少、错了怎么退"的完整计划。
  2. 决策与执行断裂：计划是脑子里的，成交是手动的，事后无法判断亏损来自策略错还是执行错。
  3. 执行与复盘断裂：券商对账单是一堆流水，无法与当初的信号做逐笔匹配归因。
  4. 复盘与进化断裂：策略改参数靠感觉，缺少"真实成交反馈 → 成本模型校准 → 参数重优化"的机械闭环。

现有工具（同花顺、通达信、东财、各类选股器）解决的是"看行情 + 写指标 + 出信号"，不解决策略资产化与可验证进化。本系统以"策略"为一等公民，把选股、区间化买卖计划、回测验证、真实成交反馈、策略进化串成一条可追溯、可复现的流水线。

1.2 产品定位

维度 定位
产品名称 AlphaForge · 阿尔法熔炉（英文工程名 alphaforge，前缀 af）
命名寓意 Forge＝熔炉：策略须经反复加热、锻打、淬火、去杂质，才能留下可用之物——正对应进化 Harness 的「搜索 → 稳健性闸门 → 淘汰劣质个体」流程
用户规模 单用户为主（个人交易者），架构预留 2–10 人小工作室
部署形态 本地优先（个人 PC / 家庭服务器 Docker Compose），数据与策略不出本机
市场范围 A 股主板 / 创业板 / 科创板 / 北交所、ETF、可转债；股指期货（IF/IH/IC/IM）；预留港美股
交易频率 日频调仓 + 盘中区间触发，最高到分钟级，不做 tick 级高频
决策权 系统只出计划与区间，人做最终下单决策；V1 不接自动下单
核心差异 ①区间化买卖建议（非单点信号）②真实成交反馈驱动的策略进化 Harness

1.3 设计原则

  1. 可复现优先于好看：任何回测结果必须能由「代码版本 + 参数 + 数据快照」三者唯一重建。
  2. 风控前置：风控是不可被策略覆盖的一票否决层，位于信号之后、计划之前。
  3. 区间优于点位：不输出"买在 12.34"，输出"建仓区间 12.10–12.45，分批比例 4:3:3"。
  4. 真实成本入模：手续费、印花税、滑点、冲击成本、涨跌停不可成交，全部进撮合模型，否则回测必虚高。
  5. 反馈闭环机械可执行：进化不是手工调参，是有适应度函数、有搜索器、有稳健性门槛的自动化流程。
  6. 数据诚实：免费源的能力边界（无 Level-2、北向实时数据已停披露）在 UI 上明示口径，不制造精度幻觉。

1.5 术语表

术语 定义
策略（Strategy） 由「股票池 + 因子/规则 + 参数 + 调仓频率 + 风控约束」构成的可执行决策单元
策略 DNA 策略参数的可编码向量表示，供搜索器与进化算法操作
区间（Zone） 带上下界与置信度的价格带，代替单一点位作为买卖执行参考
PIT（Point-in-Time） 数据在历史某一时点"当时可见"的版本，防止未来函数
未来函数 回测中使用了当时尚不可得的信息（如用当日收盘价决定当日开盘买）
生存偏差 回测样本只含存续股票，剔除退市股导致收益虚高
OOS / IS 样本外 / 样本内
Walk-Forward 滚动前推验证：滚动窗口内优化，紧邻其后区间验证
PBO 回测过拟合概率（Probability of Backtest Overfitting）
DSR 去通胀夏普比率（Deflated Sharpe Ratio），对多重试验次数做惩罚
交易计划卡 一笔交易的完整执行卡：方向、区间、仓位、止损、目标、失效条件
主力资金 按单笔成交金额分层的"超大单+大单"净流入近似口径
基差 股指期货价格 − 现货指数价格；负值为贴水，年化后即对冲成本

web  ──HTTP──►  api  ──►  engine
                 │          │
                 └──►  core ◄──┘
规则 说明 违反后果
core 不依赖任何上层包 core 只含模型、DTO、常量、工具 循环依赖，无法独立测试
engine 只依赖 core 计算逻辑不得调用 api 的 service 计算逻辑被 HTTP 层绑死，无法批量跑
api 可依赖 core 与 engine api 负责编排与鉴权，不含计算 计算散落在路由层，回测与实盘口径分叉
engine 禁止 import api 通过任务参数传入配置，不反向取 违反后 engine 无法脱离 Web 进程运行
web 只通过 HTTP/WS 访问 禁止在前端重算因子或指标 前后端口径不一致，最常见的"图上看是买点、系统说不是"

5.3 适应度函数定义（v1 默认）

fitness = w1·z(年化收益)
        + w2·z(-最大回撤)
        + w3·z(夏普)
        + w4·z(WF_OOS_夏普)          # 稳健性权重不低于 0.25
        - w5·z(年化换手率)            # 成本惩罚
        - w6·z(与现有策略池最大相关性)  # 分散化惩罚

默认权重：w1=0.20, w2=0.25, w3=0.15, w4=0.25, w5=0.08, w6=0.07
硬约束：最大回撤 ≤ 25%，年化换手 ≤ 30 倍，交易次数 ≥ 100，持仓天数中位数 ≥ 3

5.4 防止"进化出废策略"的四道闸门

闸门 检查内容 不通过处理
G1 数据闸门 数据快照完整、无未来函数、无生存偏差 直接拒绝评估
G2 稳健闸门 WF OOS 为正、PBO < 0.5、参数邻域平台区 适应度打折或淘汰
G3 成本闸门 扣真实成本后仍为正；换手未超限 淘汰
G4 相关性闸门 与已上线策略相关性 < 0.8 淘汰或仅归档

验收标准

  • 用同一随机种子重跑进化，冠军个体与适应度完全可复现。
  • 构造一个纯噪声策略（随机买卖），进化 200 代后不得通过 G2（PBO 应显著偏高），系统需明确标记"无法区分于随机"。
  • 真实成交导入后，滑点模型参数发生变化，且再次回测的净收益向实盘靠拢（偏差绝对值下降）。

实时与批次是两条独立的路（ADR 0007）：hq.sinajs.cn 一请求多代码、1 秒级刷新， 用于盘中报价与分时；Market_Center 一次拍平全市场、要翻 56 页，用于日频同步。 实时范围仅覆盖「当前标的 + 自选 + 7 大指数」，需要全市场同一时刻截面的指标 （涨跌家数、涨停家数、市场温度、涨跌幅榜）不得声称实时，界面上必须区分标注。
