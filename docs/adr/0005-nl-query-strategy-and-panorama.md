# 0005 · 自然语言选股、可编辑策略与市场全景

- 状态：已采纳
- 日期：2026-11-06

## 背景

三处缺口同时暴露：

1. 选股只有四个内置策略，「想问什么就只能跑什么」，没有同花顺问财那种一句话选股
2. 策略是代码里的常量（`STRATEGY_MAP`），用户改不了也存不下自己的思路
3. 行情页只有自选 + 单只标的，看不到市场整体：涨跌宽度、各大指数、情绪温度都没有

三者看着是三件事，其实共享同一层：**「条件」需要一种统一的表示**。
AI 解析出来的是条件，用户在表单里点的也是条件，存进策略文件的还是条件。
先把这层定下来，三件事才能各自落地而不互相打架。

## 决策

### 1. 指标词典是核心资产，不是模型

`core/fields.py` 里 34 个 `Field(key, label, unit, kind, aliases, group, ops, direction)`：

- `aliases` 是中文同义词表：「净资产收益率 / ROE / 股本回报率 / 净资产报酬率」→ `roe`
- `kind ∈ num/bool/cat`：数值比较、形态布尔、分类相等，三种匹配语义各自独立
- `unit` 同时是**默认单位**：写「ROE 大于 15」按 `%` 解释，写「市值大于 500」按 `亿`
- `options` 由演示池反推（行业 19 个、板块 3 个），前端下拉直接取用，不在 UI 里硬编码

> 架构谁都能抄，这张表抄不走。新增一个字段 = FIELDS 加一条 + 因子板补一列，
> 解析器、条件构造器、策略文件、字段下拉会同时认出来。

### 2. 规则为主，模型兜底

`engine/nlquery.py` 的解析顺序是刻意定死的：

```
排除词（不要/排除/剔除） → 数量（前 N / 取 N 只）
→ 排序（按 X 排序 / 最大最小）→ 逐片段匹配「指标 + 阈值」
→ 行业 / 板块 / 指数成分 → 命中的固定说法 → 剩余片段交给模型 → 仍未识别则报出来
```

- 模型只在 `AF_LLM_BASE_URL` + `AF_LLM_API_KEY` 同时存在时启用，
  **没有 key 也能完整跑规则链路**——演示环境不能因为缺一个外部服务就变成砖头
- 模型只做「把片段翻成条件」，不做执行，也不改结果
- 未识别的片段原样回传（`unresolved`），界面显式提示，不静默丢弃

几个必须处理的中文坑：

| 说法 | 容易错的做法 | 正确做法 |
| --- | --- | --- |
| 20 日**跌幅**超过 15% | `mom20 > 15` | 识别负向词 → 取负号 + 翻转比较符 → `mom20 < -15` |
| ROE **不低于** 15% | 「低于」先命中 → `roe < 15` | 比较词按长度降序匹配 |
| 市盈率 10 到 20 倍 | 拆成两条 `pe>10`、`pe<20` | 合并成 `between`，同字段多约束取交集 |

### 3. 三个入口共用一套条件模型

```
{ field, op, value }  +  后端 _label() 生成中文
      ↑                        ↑
AI 解析           条件构造器           持久化策略
```

中文标签**只在后端生成**。前端如果自己拼一份「ROE ≥ 15%」，早晚会和后端的说法
分叉，出现「界面写 A、结果写 B」——这是这类工具最掉分的地方。
前端只在「刚加进来、还没跑过」时用一份临时描述兜底，跑完立刻被后端标签覆盖。

### 4. 列存因子板

`engine/factor_board.py` 把整个池子的 34 个字段一次算完，按列存放：
`columns["pe"] = [12.3, 8.1, ...]`。

- 条件筛选是「逐列比较 + 与掩码」，不再是「每只票、每个条件各算一遍」
- 因子加权与条件筛选**共用同一份数据**，混合模式不会算两遍
- 按 `(交易日, 池子指纹)` 缓存，池子变了自动失效，超 4 份清空

### 5. 策略三态，界面上不出现 mode 这个词

| 用户设了什么 | 执行形状 | 结果 |
| --- | --- | --- |
| 只有权重 | `factor` | 全池多因子打分排序 |
| 只有条件 | `filter` | 命中即入选，按排序字段（默认涨跌幅）排 |
| 权重 + 条件 | `hybrid` | 先卡条件，再在命中池内打分 |

- 纯条件模式下 Z 值加权和恒为 0，界面**不显示「综合分 0.0」**，
  改显示真正决定顺序的 `rank_value`——显示一个恒为 0 的假指标比不显示更糟
- 内置策略不可直接改（`builtin: true` → 保存即另存副本），避免「演示数据被改坏」
- 没有指定排序时会兜底按涨跌幅排序，但响应里带 `implied: true` + `rank_hint` 说明，
  **不静默改变用户预期**

### 6. 指数按成分加权合成，温度是可核对的加权和

- 7 个指数（上证 / 深证 / 创业板 / 科创 50 / 沪深 300 / 上证 50 / 中证 500）
  的点位由成分股**按流通市值加权**合成，首日归一、末值缩放到锚点，
  与成分股涨跌严格一致——不另造一条随机数曲线
- 成分划分按交易所 / 板块 / 市值排名切分，保证沪深 300 与中证 500 不重叠
- 市场温度 0–100 是五因子加权：涨跌家数 30% / 涨停强度 15% / 指数动量 20% /
  量能 15% / 站上 MA20 比例 20%
- 界面把**分项拆解连同原始值一起显示**（`22 涨 / 18 跌`、`成交额 1.00× 20 日均值`），
  0–100 这个数字必须能被核对，否则它只是一个装饰性指针

### 7. 温度表盘避开红绿

红绿在本项目里只表示涨跌（见 ADR 0003）。温度是**情绪刻度**，不是涨跌，
所以用 冷灰 → 蓝灰 → 主色 → 蓝 → 琥珀 的单色梯度，指针与刻度自绘 SVG，
不引 ECharts gauge（省几百 KB，也避免默认样式与面板语言打架）。

## 后果

- 新增指标的成本降到「两张表各加一行」，不用碰解析器与界面
- AI 解析在无 key 环境下仍然可用，但召回边界受别名表覆盖度限制；
  未识别片段会明示，用户可改用条件筛选补上
- 策略以 `StrategyPayload` 落盘，内置策略与自定义策略同结构，
  区别只有 `builtin` 标记与「不可覆盖」规则
- 全景条在桌面端常驻、平板/手机折叠为一行摘要：它回答「今天是什么天气」，
  但小屏首屏应该先给「我在看的这只票」
