# 0001 · 四层分包与确定性合成行情

- 状态：分层部分**仍然有效**（层次由 3 层扩为 4 层，见 0006）；合成行情部分**已被 0006 取代**
- 日期：2026-11-06
- 关联：SRS K-12（复权一致性）、FR-DAT-06（涨跌停）

## 背景

个人工作台的第一版要在没有数据源的前提下跑通「行情 → 选股 → 信号 → 持仓 → 风控」全链路，
同时保证后续接入真实数据源时不需要重写上层。两个问题必须一起解决：

1. 计算代码与传输层、UI 不能耦合，否则换数据源或加 CLI 会牵一发动全身；
2. 演示数据必须可复现，否则截图、测试快照、评审时的数字对不上。

## 决策

**四层分包**：`core`（领域与纯函数）→ `engine`（计算）→ `api`（传输）→ `web`（界面）。
硬约束：`core` 不依赖任何上层；`engine` 只依赖 `core`；`web` 只经 HTTP 访问。

**确定性合成行情**：每个标的的随机种子为 `zlib.crc32(f"{code}|{salt}")`，
序列由 `random.Random(seed)` 生成，不依赖进程级的 hash 随机化。
因此同一 `code` + `salt` 在任何机器、任何时间都产出逐字节一致的历史。

价格存**原始价 + 复权因子**，前复权在返回时即时合成、不落库，
避免「一份数据多种口径」导致的缓存不一致。

## 备选方案与被否理由

| 方案 | 否决理由 |
| --- | --- |
| 单文件 Flask + 前端模板 | 计算与视图耦合，无法单测指标；换数据源要改路由 |
| pandas + numpy 做指标与绩效 | 镜像 ~900MB；指标窗口固定、标的仅 40 只，标准库足够；wheel 与 Python 版本强绑定 |
| 随机数直接用 `random` 默认种子 | 每次启动行情都变，截图与快照无法比对 |
| 预生成 CSV 落盘 | 需要维护数据文件、体积大，且改参数要重新生成 |

## 后果

- 收益：`core` 可被回测、离线批处理、CLI 直接复用；冷启动 < 1s；镜像 ~180MB
- 收益：`AF_SALT` 一个变量就能切换整套演示数据，便于多环境隔离
- 代价：分层靠约定与评审维持，尚未接 `import-linter` 自动校验
- 代价：合成数据只能验证链路正确性，不能用于策略有效性判断

## 后续修订（2026-11-06，第五轮）

- **合成行情整体移除**：`SYMBOLS` 演示池、`AF_SALT`、`zlib.crc32` 种子全部删除，
  改为真实行情落 SQLite，见 [0006](0006-real-market-data.md)。
- **层次由 3 层扩为 4 层**：`core ← data ← engine ← api → web`。新增 `data`
  专管抓取、落库与因子宽表，`engine` 不再自己造数据。
- **分层从「约定」升级为「可失败的门禁」**：上面那条「尚未接 `import-linter` 自动校验」
  的代价已消除，但**没有引入 import-linter**——它需要额外依赖与配置文件，而这里要查的
  规则很窄。改为 `scripts/check_layers.py`（约 200 行，纯标准库 AST），`make layers`
  即跑，退出码即结论。它比 import-linter 多查三条 import-linter 表达不了的规则：

  | 规则 | 为什么 import-linter 查不了 |
  | --- | --- |
  | `core` 不得 import `sqlite3`/`urllib`/`os`/`pathlib` 等 I/O 模块 | 这是「模块内容的性质」，不是包之间的依赖关系 |
  | `core` 第三方依赖只允许 `pydantic` | 同上，需按 stdlib 白名单逐层判断 |
  | `engine` 不得 import `sqlite3`（必须经 `repo`） | 同上 |

  代价：只静态检查 import 语句，查不出「`engine` 拼 SQL 字符串但没 import sqlite3」
  这类语义越界，那一层仍需代码评审兜底。
