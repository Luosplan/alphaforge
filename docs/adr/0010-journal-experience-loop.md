# 0010 · 复盘经验库：把「为什么没买」变成下一轮选股的输入

- 状态：已采纳
- 日期：2026-11-27
- 影响：新增 `engine/journal.py`（每日 md、归因、滚动经验、模型复核）、`routers/journal.py`
  五个接口、前端「复盘日记 → 经验库」页签；`paper` 增加 `screens` / `execution` 两卷
  流水与 `ORDER_LLM` 状态；`_next_plans` 的候选宽度从 `top_n` 放宽到 20、挂单前多一道
  模型复核。**回测与撮合规则未改，`MODEL_VERSION` 不变。**

## 1. 问题：每天都在选股，账户三个月没动

复盘日记一直有，但它只回答「今天赚了多少」，回答不了用户真正问的那句：
**「这只票后来涨了 8%，你为什么没买？」** 两个账户的真实状态是：

- 打板：持仓 2 只 + 1 张待成交委托，`top_n=3` 名额占满，每天新选出的票全部落在
  「仅备选 · 仓位已满」；
- 波段：持仓 3 只，同样满额，三只候选全是备选；
- 而 `time_stop` 已被自进化推到 7~8 天。持仓不释放 → 名额永远不空 → 新票永远进不来。

结论是：**这不是选股问题，是「名额 + 持有期」的结构问题**。但这句话在旧页面上看不出来——
卡片只写「仅备选」，没有人把它和「今天有多少只票涨了 3% 以上」对起来。

## 2. 决策一：把「机会」钉成一个可复核的口径

「T+1 波动大于 3%」= **当日开盘买入、次日开盘就能卖出时的收益 ≥ 3%**。两头都用开盘价：

- 本系统的成交价就是次日集合竞价的成交价（见 `paper` 文件头），用收盘价衡量会出现
  「账上说赚、实际卖不到」的差，这种记录总结出来的是幻觉；
- 只算能卖的时点，不算盘中最高价。盘中摸到 +8% 但开盘只有 +1% 的票，不算机会——
  那是拿「不可成交的价格」骗自己。

## 3. 决策二：射程内与射程外分开统计（这一条最关键）

11-26 实测：227 只票满足 ≥3%，其中 **210 只是「昨天没涨停」**。打板策略只做涨停池，
这 210 只对它根本不是机会。若按整体算抓到率：

```
抓到率 = 0 / 227 = 0%   →  结论「选股全错，要放宽条件」
```

这个结论是错的，而且会把人推向「去买没涨停的票」——那是另一条策略，不是修这套规则。
所以归因分成两级：

| 级别 | 包含 | 用途 |
| --- | --- | --- |
| **射程内** | 已买入 / 挂了没成 / 没挂单 / 没进候选 | 计入抓到率，是这套规则「够得着却没吃到」的钱 |
| **射程外** | 不在池子（没涨停 / 连板超区间 / 成交额不足 / 动量未进前列） | 单独记一笔，只为知道钱漏在哪 |

`reach_rate = caught / (caught + in_range)`。射程外的票永远不进「教训」一节的结论。

## 4. 决策三：模型只能否决，不能新增

选股挂单前把《经验》+ 最近三天 md 整段喂给模型，让它判「哪几只今天不该买」。

- 只给否决权：新增标的、改仓位、改止损全部不给。这三件事改错一次就是真金白银，
  而「这只票和历史上亏过的那类像」正是文本经验最擅长的判断；
- 未配置模型 / 限流 / 超时 → 照常挂单。兜底方向必须是「照常买」，
  否则一段网络故障就把「模型在把关」变成「模型在当刹车」；
- 同一天同一批候选只问一次（`journal._ADVICE`），`force=true` 重算计划卡不重复付费；
- 被否决的卡片留着，状态写「模型否决 · 经验库里这类票反复亏」，理由单独一行显示。
  否决不占名额，后面一名顺延。

## 5. 后果与已知代价

- 收盘任务多两次模型调用（每条策略一次复核 + 一次经验重写），各 40~60 秒超时。
  失败不影响账户推进：经验库那一步单独 try，出错只记进 `steps`。
- 归因依赖**收盘时落盘的流水**（`screens` = 当天选了谁、`execution` = 哪张委托被哪道
  闸门挡掉）。因子表只留最近几天，T+1 收盘时昨天那天的连板数已经查不回来——
  所以流水必须在当天写下来，不能事后重算。上线前的旧账户没有这两卷，头两天归因会
  退化成「不在池子」，属预期。
- 《经验》每天重写一次。模型调用失败时**保留上一版**，不用规则版覆盖——
  一次网络抖动不该把库里写得好的东西降级成统计表。
- 模型说的话不是规则：它引用的是经验里的数字，经验里没有对应教训时它应当放行
  （实测空库时 20 只候选全部 pass，符合预期）。
