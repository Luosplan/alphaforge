# 0007 · 实时行情：批量轮询 + 短 TTL 缓存

- 状态：已采纳
- 日期：2026-11-10
- 关联：0006（真实行情落库）、SRS FR-QTE-01 / NFR-P-02

## 背景

0006 把数据换成了真实行情，但那是**同步批次**：日线、快照、因子表都是
"上一次跑 `sync` 那一刻"的截面。用户在交易日盘中打开行情页，看到的还是
上一交易日的收盘价，界面上没有任何一行字说明这一点——这不是数据错了，
是**数据被当成了实时数据在用**。

典型观感：

- 14:00 打开茅台，价格还是上周五的 1453.00，而真实价在 1440 附近震荡
- 分时图停在某个历史时点不动（腾讯分时接口已整片返回空，代码里静默退回了缓存）
- 自选股、指数点位、成交额全都不会变

## 决策

### 1. 实时报价走 `hq.sinajs.cn`，一次问一批

```
https://hq.sinajs.cn/list=sh600519,sz000001,sh000001
→ var hq_str_sh600519="贵州茅台,1438.230,1444.990,1439.610,...";
```

选它的理由：**一次请求可以带几百个代码，延迟 1 秒级**。这与 0006 用的
`Market_Center.getHQNodeData`（全市场横截面，翻 56 页、十几秒）是两条路，
不能混用——后者是"全市场一次拍平"，前者是"指定几只问当前价"。

实时覆盖范围：**当前标的 + 自选 + 7 大指数**（十几只）。全市场 5578 只的
实时截面是另一个量级（70 批请求 / 轮），没有做，见下方"边界"。

### 2. 缓存按「代码」存，不按「请求」存

```
_cache: {code: (stamp, quote)}
```

按请求集合做 key 会互相顶掉：切一只票就换一个集合，缓存永远打不中。
按代码存之后，不同页面要的子集可以复用同一份。

TTL 3 秒，与前端轮询周期一致。三条语义要分清：

| 概念 | 含义 |
| --- | --- |
| TTL 内 | 直接用缓存，不发请求 |
| TTL 过期但上游取到 | 覆盖缓存，`live=True` |
| 上游取不到、有旧值 | 返回旧值并标 `stale=True` + `age`，界面降级但不消失 |
| 上游取不到、旧值也超龄 | 干脆不给，价格位显示「—」 |

**上游失败不抛异常**。轮询是持续行为，这一轮失败下一轮自然补上；抛异常
只会让前端把整个报价区打红，而用户真正需要的是"这个价是几秒前的"。

### 3. 时段判定放 `core`，用报价日期反推节假日

`alphaforge_core/market_session.py` 是纯函数：传入"现在几点"和"报价的日期"，
返回 `pre / auction / open / break / closed / weekend / holiday`。

**不维护节假日表**，因为表会过期。判据是：如果按钟点算此刻应该在盘中，
但行情源返回的日期不是今天，那今天就是休市。行情时间戳永远不会说谎，
日历表会。

`core` 里不能出现 `os` / `time` / `sqlite3`，所以时钟由调用方注入——
这条约束由 `make layers` 守着（见 0001 的后续修订）。

### 4. 前端：递归 `setTimeout` + 可见性暂停 + 收盘降频

| 做法 | 为什么不用另一种 |
| --- | --- |
| 递归 `setTimeout` | `setInterval` 在响应慢于周期时会把请求堆起来，越堆越晚 |
| 请求带序号，只认最新 | 快速切票时慢响应会盖掉新标的的报价 |
| `visibilityState !== 'visible'` 就跳过 | 切到别的标签页还在 3 秒一次打接口，纯烧配额 |
| 收盘后降到 60 秒 | 完全停掉的话，页面放一晚上第二天开盘还得手动刷新 |

### 5. 分时改用新浪 `CN_MinlineService`

腾讯那条分时接口现在整片返回空，代码里静默退回了 `minute_cache`——分时图
"不动"的观感就是这么来的，而且它不报错，很难发现。

新浪这条给到**当前分钟**，还附带 `avg_p`（真实均价线），比原来拿成交量加权
算的近似值更准。分时按 20 秒追一次：它本来就是按分钟聚合的，3 秒刷一次拿到
的还是同一根柱子。

## 实测踩到的坑

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| **北交所字段长度不同** | 沪市 33 段、深市指数 32 段、**北交所 39 段**。按"倒数第三位是日期"取，北交所的 `ts` 会变成 `8300000 B` | 按格式扫一遍找 `YYYY-MM-DD`，紧跟的那个字段才是时间 |
| **`hq.sinajs.cn` 校验 Referer** | 不带 `Referer: https://finance.sina.com.cn/` 一律 403 | 写进 `HQ_HEADERS` 常量，不是可选项 |
| **停牌/写错代码返回空串** | `var hq_str_xxx="";`，HTTP 200 | 解析时跳过，不算错误 |
| **停牌时 `price=0`** | 涨跌幅算成 −100% | 用 `prev_close` 兜底算参考价（与 `_normalize` 同一口径） |
| **TTL 缓存把新值当旧值** | 抓到数据后忘了回填 `fresh`，紧接着的"没取到"分支把刚拿到的价标成 `stale`，还算出 `age = −0.1` | 写库后同步回填返回集合 |
| **成交量单位不统一** | 股票给「股」、指数给「手」 | 股票 ÷100 折手，指数量纲原样保留（下游不展示） |
| **分时接口不给昨收** | 画不出基准线，涨跌颜色全线错位 | 用实时报价的 `prev_close` 补 |
| **`/quote` 与 `/live` 混用** | 分时曲线在 14:11，标价却是上周五收盘 | `/market/minute` 的 `quote` 字段也走实时 |

## 备选方案与被否理由

| 方案 | 否决理由 |
| --- | --- |
| WebSocket / SSE 推送 | 没有免费公开的推送源，自己搭中继等于把轮询挪到服务端，成本不变还多一层 |
| 前端直接连新浪 | 跨域 + 需要伪造 Referer + 把数据源地址暴露在浏览器里，且无法限速 |
| 全市场 5578 只实时 | 70 批请求/轮，最低 10 秒一轮，对免费源不礼貌；涨跌幅榜暂仍是收盘截面 |
| 每秒轮询 | 免费源 1 秒级刷新本身没有意义，3 秒已经够看 |

## 边界（界面上必须说清楚）

已经实时：个股报价（当前 + 自选）、7 大指数点位、分时曲线。

**仍然不是实时**，界面上不标"实时"：

- **全市场横截面**：涨跌家数、涨停家数、市场温度、成交额合计、涨跌幅榜
  —— 这些要的是 5578 只的同一时刻快照，属同步批次
- 日 K / 周 K / 月 K：收盘后才定稿，盘中最后一根是当日实时价的延伸
- 资金流：源本身是日频，T+1

## 后果

**得到**

- 盘中打开行情页，价格、成交额、指数点位每 3 秒自己动，标记显示行情源时间
- 收盘/休市时自动停轮询并显示"已收盘"，不会把上周五的价伪装成实时
- 上游挂掉时价格位显示旧值 + `stale` 标记，不会白屏也不会假装新鲜
- 单轮到上游只有 1 个请求（≤80 代码/批），TTL 命中时接口耗时 57ms

**代价**

- 服务端多一份进程内缓存状态；多进程部署（uvicorn workers > 1）会各自缓存，
  同一代码可能被不同 worker 各取一次。当前单进程，够用
- 免费源没有 SLA，反爬策略变化会让实时整体降级为"收盘数据"，需要靠
  `stale` 标记暴露出来而不是静默
- 涨跌幅榜与市场温度仍是收盘口径，与实时报价并排时存在"同一屏两种时间"，
  这一条只能靠界面标注缓解，彻底解决要上全市场实时截面
